# Aislador Implementation Plan

Goal: extracción offline útil de HAR por proveedor, manteniendo novedades y procedencia.
Architecture: lector/transporte común, registro de perfiles, codecs separados y
clasificador de campos/patrones; CLI + GUI local usan la misma API.
Tech stack: Python 3.11+ stdlib, unittest; codecs opcionales claramente señalados.
Spec: ../specs/2026-10-15-aislador-design.md

- [x] T1: Pruebas sintéticas lector HAR: base64, Firefox/HardFire WS, conexiones
  distintas, límites, recursos y mensajes opacos. Implementar normalización.
- [x] T2: Decodificador Nolimit offline por conexión, pruebas RC4/LZW/error.
- [x] T3: Perfiles del registro Tester-Spin; acciones/fases conocidas explícitas,
  detección sin confundir Evolution/Red Tiger ni apostar desde heurísticas.
- [x] T4: Motor/classificador, novedades con referencia y ejemplos agrupados,
  sanitización profunda, escritura segura independiente de nombre del juego.
- [x] T5: CLI/GUI, extracción de contexto por referencia, bases locales de
  patrones revisadas, docs de uso y CI.
- [x] T6: Validación en HAR reales locales de varios proveedores, revisión
  independiente, tests completos, commit/push al repo Aislador.

Review focus: un HAR parcial no puede simular init; errores y campos nuevos no
pueden desaparecer; claves nunca salir a informes; WS no mezclar sesiones;
archivos existentes no sobrescribir ni utilizar nombres del HAR como rutas.
